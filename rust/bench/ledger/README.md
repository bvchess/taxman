# The ledger: the data and the commands

What was run and what it showed: [the entry](../../docs/experiments/the-ledger-bounds-from-both-sides-2026-10.md).
The program is `examples/ledger/` (its module comment defines every field of `ledger.jsonl` and `events.jsonl`), run
from `rust/` with the non-release build of the laptop: `cargo build --profile test --example ledger --bin taxman`
(opt-level 2, debug assertions on), so `ledger` is `target/debug/examples/ledger` and `taxman` `target/debug/taxman`.
Everything here ran under `nice -n 10`.

## Files and the commands that made them

| file | command | what it is |
|---|---|---|
| `cloud.sh` | `bench/ledger/cloud.sh FIRST-LAST` (environment in its comment) | the experiment on one machine: `ledger run` with the truth hidden, then `ledger report --known results/strict.jsonl`; the cloud run of 2176..3440 is [RUNBOOK section 14](../../tools/cloud/RUNBOOK.md#14-the-ledgers-experiment) |
| `events.py` | `./events.py DIR [CHAIN.jsonl]` | what a run spent its time on, beyond the report: setup, maps and searches, stopped searches and their dual bounds, the finder's runs and the games that seeded the searches, the searches by whether n − 1 and n + 1 were proven when they began, the relations' changes by rule, the main thread's busy time, the CPU over the run's wall time; with the chain's results file over the same stretch, its seconds beside |
| `dry/` | `OUT=DIR LEDGER_BIN=target/debug/examples/ledger WORKERS=6 CPU_HOURS=2 bench/ledger/cloud.sh 1301-1500` (2026-10-17, 21:11:44 to 21:13:57 UTC, after the fix of the first cloud attempt), with DIR a scratch directory whose files were copied here | the laptop's dry run of 1301..1500, the truth hidden (the run before the fix, 20:01:50 to 20:04:16 UTC, took 595 CPU s and 145 s; its files are in d7390e1): `run/ledger.jsonl.gz` and `run/events.jsonl.gz` (gzipped after the run; the checkpoints were all deleted, every board being proven), `run.err` (its status lines), `log` (the stages' times); `report.txt` is the run's own (`cloud.sh` makes it) |
| `dry/chain.jsonl.gz` | `taxman solve 1301-1500 --threads 1 --window 1 --progress 0 --out dry/chain.jsonl`, then gzipped | the chain over the same stretch on one thread with the same build, standalone at 1301 (no game of 1300), for the comparison: 447.5 s in all (`/usr/bin/time`: 449 s wall, 446.7 s user) |
| `dry/events.txt` | `./events.py dry/run dry/chain.jsonl` | the output the entry quotes |
| `climb/` | runs of one stretch back to back (2026-10-17 and 18, 23:43 to 00:36 UTC), the non-release build, the truth hidden: `OUT=DIR LEDGER_BIN=target/debug/examples/ledger WORKERS=6 CPU_HOURS=2 [CLIMB=up\|down\|both\|off] bench/ledger/cloud.sh 1301-1500` (`dry-*`), `WORKERS=8 CPU_HOURS=0.1667 ... 2576-2700` (`mid-*`), `CPU_HOURS=0.5` (`long-*`); `*-up` and `*-off` are the climbs up only (the build of eb9dc9c, the default then: `CLIMB_LIMIT` unset, 60 s) and none (`CLIMB_LIMIT=0`), `*-both` and `*-down` the build of 55d2b2a | wedge and climb, [the entry's section](../../docs/experiments/the-ledger-bounds-from-both-sides-2026-10.md#later-2026-10-17-wedge-and-climb); each directory has `report.txt` (the run's own; before 55d2b2a it has one line of climbs, and for the runs without any it reads "-0 s", a rounding the report no longer makes), `log`, `run.err`, `events.txt` (`./events.py` on `run`) and `run/ledger.jsonl.gz`, `run/events.jsonl.gz` |
| `finder/` | runs back to back (2026-10-18, 01:01 to 01:15 UTC), the non-release build of 4621d97, the truth hidden: `OUT=DIR LEDGER_BIN=target/debug/examples/ledger WORKERS=6 CPU_HOURS=2 LNS_SECONDS=1 bench/ledger/cloud.sh 1301-1500` (`dry-on`, and `dry-off` with `LNS_SECONDS=0`, last), `WORKERS=8 CPU_HOURS=0.25 LNS_SECONDS=1\|0 ... 2576-2700` (`mid-on-a`, `mid-off-a`, `mid-off-b`, `mid-on-b`, in this order) | the finder in the ledger, [the entry's section](../../docs/experiments/the-ledger-bounds-from-both-sides-2026-10.md#later-2026-10-17-the-finder-in-the-ledger); each directory has `report.txt`, `log`, `run.err`, `events.txt` (`./events.py` on `run`) and `run/ledger.jsonl.gz`, `run/events.jsonl.gz` |
| `climb_limit.py`, `climb_limit.txt` | `./climb_limit.py DIR`, with DIR the second cloud run's directory (2176..3440, 48 core-hours on 64 workers; its 2 MB events file and 9 MB ledger are not kept here) | what a longer climb limit would cost, from that run's events: the table the default of 60 s rests on |
| `cloud-20261017-stopped/` | `bench/ledger/cloud.sh 2176-3440` on a `c8g.16xlarge` with 64 workers (2026-10-17, 20:31:21 to 20:40:21 UTC, stopped by a signal after 9 minutes), the three small files of `~/ledger` and the output of `./events.py` on its run | the first cloud attempt, before the fix: `report.txt` (nothing proven, 1,299 CPU s), `log`, `run.err` (its status lines), `events.txt`; the 21 MB events file and the 8 MB ledger are not kept |
