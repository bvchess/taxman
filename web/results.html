Chapter 7

The results

An optimal game for every n from 1 to the end of the chain, each with its proof. Here is every one of them, what they show together, and what is still open.

Every game

Choose any game of the chain. The explorer shows what the chain records for it: what the player and the taxman each collect in its optimal game, how the game was proven, how many promotions it makes, and what its search cost. For the games up to 100 it draws the game itself, on its board.

A game’s record, precisely

The record is the game’s line of the results file. Its in_the_bag is ΣU*, the score with no promotions, and its time is seconds.total, on the machine of its run: a laptop to 2,175, larger machines past it. A game of the prime formula or of the bounds store sets up no frames, so it records no ΣU* and no candidates (the frame solver’s reference; the runs).

The top half carries most of each score: U*, the numbers above n/2 that descending greedy keeps, scores ΣU* before any promotion. The promotions add the rest, and the search chooses them. Its cost rises steeply with n: the search of game 21 explores 1 node, and the search of game 5060 explores billions, in about hours.

The player’s share

Hensley’s theoremHensley, 1988proved, the paper

The player’s share tends to a constant, more than 1/2 and at most 35/48.

Precisely.The limit C of opt(n) / (n²/2) exists, and 1/2 < C ≤ 35/48: D. Hensley, “A winning strategy at Taxman”, The Fibonacci Quarterly 26 (1988) 262–270. The share has the same limit, since 1 + 2 + ⋯ + n = n(n + 1)/2 and (n + 1)/n tends to 1.

Every game can be wonFranklín and Moniot, Theorem 5proved, the paper

The player can beat the taxman in every game but 1 and 3.

Precisely.Their born-free matching wins every game n ∉ {1, 3} but 7 and 13, which they win by hand: A. F. Franklín and R. K. Moniot, Discrete Applied Mathematics 339 (2023) 166–171 (what the paper proves).

An optimal game wins a share of the board: its score, opt(n), divided by 1 + 2 + ⋯ + n, the total of the board. The player beats the taxman when the share is above one half. In every game of the chain but 1 and 3, it is.

In 1988 Douglas Hensley proved that as n grows, the share tends to a constant: more than 1/2, and at most 35/48, about 73%. So the player beats the taxman in every game large enough, and in the long run the taxman keeps at least 13/48 of the board, more than a quarter. The theorem does not say what the constant is.

The share near 63%measured, evidence on GitHub

From game 4,000 on, the share stays between 62.8% and 63.0%.

Precisely.The share opt(n) / (n(n + 1)/2) stays in that range in every game from 4,000 to 5060, by the scores of results/optimal.jsonl.gz. It measures finitely many games, and proves nothing about C.

The chain’s games put the constant near 63%. The share swings widely in the first games and settles as n grows: from game 4,000 on it stays between 62.8% and 63.0%, and game 5060 wins 62.9%. That is a measurement of finitely many games, not a proof about the limit.

What the games show

One optimal set, to 424measured, evidence on GitHub

Every game up to 424 has exactly one optimal set; game 425 has two.

Precisely.The prover lists the optimal sets of the games 2 to 989: one in every game up to 424, and two or three in 30 games from 425 to 779 (the evidence).

Most games have exactly one optimal set. Every game up to 424 has one, and game 425 is the first with two. They differ by an exchange: one plays 110, 132 and 168, the other 98, 150 and 162, and both trios sum to 410 (chapter 4).

So a score is the same whoever finds it, but a game need not be. Where a game has several optimal sets, the chain keeps the one its search found (the games with several).

How far an optimal game falls shortmeasured, evidence on GitHub

Every recorded game up to 4,949 makes the most moves it can, but 833, 834 and 835, which make one fewer.

Precisely.The prover settles ℓ(n), the most moves of a game of n, for every n from 2 to 4,949. Whether the shortfall is bounded is open.

Nor does an optimal game always make as many moves as it can. In game 833, every optimal game makes 362 moves, yet a game can make 363, and the best of those scores 29 less. Chapter 1 shows the trade.

What is open

Statement Uand corollary X8certified game by game, evidence on GitHub

Some optimal game plays every source descending greedy keeps in layers 3 and up.

Precisely.Some optimal set of n contains U*≥3, and then ΣU* + P*(Πn) = opt(n) (statement U). It holds wherever the prover has proven opt(n), from 2 to 2,175.

Four statements of the theory are open, and one of them matters most. Statement U says that some optimal game plays every number of U* with three or more prime factors (chapter 3). Every score past 2,175 rests on it: each is the best score of the frame model, which is opt(n) wherever U holds. U holds in every game up to 2,175, because the prover proves those scores on the whole board. Past them it is open.

The sources conjectureConjecture S1certified game by game, evidence on GitHub

No playable set of sources outweighs U*.

Precisely.Every playable set S of sources has ΣS ≤ ΣU* (S1). The span conjecture (♦) gives (★), which gives S1, and the check of (♦) passes in every game up to 100,000.

The other three are about the top half alone. The sources conjecture says that U* is the heaviest set of sources, the numbers above n/2, that can all be played: that descending greedy, which keeps each source it can from the largest down, always chooses best. Two stronger statements, (★) and (♦), would each prove it, and a quick computation checks (♦): it holds in every game up to 100,000. No score rests on these three, since the frame model takes U* as it is.

The complexity of TaxmanAn open questionopen, evidence on GitHub

How hard is it to find opt(n)?

Precisely.Their Theorem 2 makes the game on a graded poset NP-hard, even on two ranks with unit weights. The complexity of Taxman itself is open, with the theory’s other open questions.

Last, how hard is Taxman? Franklín and Moniot proved a more general game NP-hard: Taxman played on any order of things in levels, where a move removes everything below it. So a fast method for that game would give fast methods for a large family of hard problems, none of which has a known fast method. Whether Taxman itself, on the numbers 1 to n, is that hard is open.

The data, and how to check it

A line of the file

One JSON line a game, in order of n: n, score, moves in the order played, promotions, proof, method, in_the_bag, setup, nodes, seconds, and assumes, what the proof rests on beyond the frame model (a results line; the proof kinds).

What the verifiers check

The frame solver’s verifier also sets up the search problems of each repeat and of the game it repeats, and compares them. The verifier in Python also checks each score against Franklín and Moniot’s upper bound (the verifiers).

Every game of the chain is one line of one file, results/optimal.jsonl.gz: its moves in the order played, its score and promotions, how it was proven, and what that proof rests on. Two programs that share no code check every line, from the top of the repository:

Print the line of game 21
gzip -dc results/optimal.jsonl.gz | sed -n 21p
Build the frame solver
cd solver/frame && cargo build --release && cd ../..
Check every game with the frame solver’s verifier
solver/frame/target/release/taxman verify-results results/optimal.jsonl.gz
Check every game again, with a verifier in Python that shares no code with it
python3 solver/tools/check_results.py results/optimal.jsonl.gz

Both verifiers replay each game: every move legal, the largest prime first, no move left at the end, and the score as recorded. They check each score against the game before it, which it can beat by n at most, and they work out each line’s proof and what it rests on again, so that an edit to the file cannot change either.

A replay shows that a game is legal and scores what it says, but not that no game scores more. That is what the proofs are for, and each line names its own. The prover proves the scores from 2 to 2,175 again, on the whole board, and its guide gives the commands. The scores alone are also in the format of the OEIS, in results/b019312.txt.
