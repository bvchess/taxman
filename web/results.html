Chapter 8

Results

For every game from game 1 to game the end of the chain, the chain records an optimal game and the rule or search behind its score. Together the games show where the player's share settles. A few questions are still open.

Every game

Choose any game of the chain. The explorer below shows what the chain records for it: what the player and the taxman each collect in an optimal game, how the chain proves the score, how many promotions the optimal game makes, and what its search cost. For games up to 100 it also draws the moves on the board.

A game’s record, precisely

The record is the game’s line of the results file. Its in_the_bag is ΣU*, the score with no promotions.

One run made every line, from November 1 to 6, 2026, on one machine with 88 threads, and it worked on up to four games at once. A game’s time, seconds.active_all_runs, counts only the time that at least one thread worked on it, not the time it waited while the threads worked on other games (the frame solver’s reference; the run).

Most of each score comes from the top half: U*, the numbers above n/2 that descending greedy keeps. The promotions add the rest, and the search chooses them. The search grows steeply with n: in game 21 it explores 1 node, and in game 5,060 it explores 1.2 billion, in about 2.4 hours.

The player’s share

Hensley’s theoremHensley, 1988proved, the paper

As n grows, the player’s share tends to a limit: more than 50%, and at most 35/48, about 73%.

Precisely.The limit C of opt(n) / (n²/2) exists, and 1/2 < C ≤ 35/48: D. Hensley, “A winning strategy at Taxman”, The Fibonacci Quarterly 26 (1988) 262–270. The share has the same limit, since 1 + 2 + ⋯ + n = n(n + 1)/2 and (n + 1)/n tends to 1.

Every game can be wonFranklín and Moniot, Theorem 5proved, the paper

The player can beat the taxman in all but games 1 and 3.

Precisely.Their born-free matching wins every game n ∉ {1, 3} but games 7 and 13, which they win by hand: A. F. Franklín and R. K. Moniot, Discrete Applied Mathematics 339 (2023) 166–171 (what the paper proves).

An optimal game wins a share of the board: its score, opt(n), divided by 1 + 2 + ⋯ + n, the total of the board. The player beats the taxman when the share is above one half. In every game of the chain except games 1 and 3, it is.

In 1988 Douglas Hensley proved that as n grows, the share tends to a limit: more than 50%, and at most 35/48, about 73%. So in the long run the taxman keeps more than a quarter of the board. The theorem does not say what the limit is.

The share near 63%measured, evidence on GitHub

From game 4,000 on, the share stays between 62.8% and 63.0%.

Precisely.The share opt(n) / (n(n + 1)/2) stays in that range in every game from game 4,000 to game 5060, by the scores of results/optimal.jsonl.gz. It measures finitely many games, and proves nothing about C.

The chain’s games put the limit near 63%. The share swings widely in the first games and settles as n grows: from game 4,000 on it stays between 62.8% and 63.0%, and game 5060 wins 62.9%. That is a measurement of finitely many games, not a proof about the limit.

What the games show

One optimal set, to game 424measured, evidence on GitHub

Every game up to 424 has exactly one optimal set; game 425 has two.

Precisely.The prover lists every optimal set of 954 of the games 2 to 989, every game to 797 among them: one in every game up to 424, and two or three in 30 games from game 425 to game 779 (the evidence).

A game usually has just one optimal set. The prover has listed every optimal set of 954 of the games 2 to 989, and all but 30 of those have exactly one. Every game up to 424 has one, and game 425 is the first with two. They differ by an exchange: one plays 110, 132 and 168, the other 98, 150 and 162, and both trios sum to 410 (chapter 4).

So the best score of a game is the same whoever finds it, but the moves that reach it need not be. Where a game has several optimal sets, the chain keeps the one its search found (the games with several).

How far an optimal game falls shortmeasured, evidence on GitHub

Up to game 4,949, every recorded optimal game makes the most moves its board allows, except in games 833, 834 and 835, where it makes one fewer.

Precisely.The prover settles ℓ(n), the most moves of a game of n, in games 2 to 4,949. Whether the shortfall is bounded is open.

Nor does an optimal game always make as many moves as it can. In game 833, every optimal game makes 362 moves, yet a game can make 363, and the best of those scores 29 less. Chapter 1 shows the trade.

What is open

Statement Uand corollary X8open, proved to game 2,530, evidence on GitHub

Some optimal game plays every source descending greedy keeps in layers 3 and up.

Precisely.Some optimal set of n contains U*≥3, and then ΣU* + P*(Πn) = opt(n) (statement U). It holds wherever the prover has proven opt(n), from 2 to 2,530.

Four statements of the theory are open, and one of them matters most: statement U, that some optimal game plays every number of U* with three or more prime factors. The scores past game 2,530 rest on it, and chapter 7 gives the evidence for it.

The sources conjectureConjecture S1open, proved to game 100,000, evidence on GitHub

No playable set of sources outweighs U*.

Precisely.Every playable set S of sources has ΣS ≤ ΣU* (S1). The span conjecture (♦) gives (★), which gives S1, and the check of (♦) passes in every game up to 100,000.

The other three are about the top half alone. The sources conjecture says that U* is the heaviest set of sources, the numbers above n/2, that are playable together: that descending greedy, which keeps each source it can from the largest down, always chooses best. Two stronger statements would each prove it, and a computation checks the stronger of the two: it holds in every game up to 100,000. No score rests on these three: the frame model plays U* whether or not it is the heaviest set of sources.

The complexity of TaxmanAn open questionopen, evidence on GitHub

How hard is it to find opt(n)?

Precisely.Their Theorem 2 makes the game on a graded poset NP-hard, even on two ranks with unit weights. The complexity of Taxman itself is open, with the theory’s other open questions.

Last, how hard is Taxman? Franklín and Moniot proved a more general game NP-hard: Taxman not on numbers but on any set of things that sit in levels, as the numbers sit under division, where a move scores one thing and the taxman takes everything below it. So a fast method for that game would give fast methods for a large family of hard problems, none of which has a known fast method. Whether Taxman itself, on the numbers 1 to n, is that hard is open.

The data, and how to check it

A line of the file

One JSON line for each game, in order of n: n, score, moves in the order of play, promotions, proof (how the chain proves the score), method, in_the_bag, setup, nodes, seconds, and assumes, what that rests on beyond the frame model (a results line; the proof kinds).

What the verifiers check

The frame solver’s verifier also sets up the search problems of each repeat and of the game it repeats, and compares them. The verifier in Python also checks each score against Franklín and Moniot’s upper bound (the verifiers).

One file, results/optimal.jsonl.gz, has a line for each game of the chain: its best score, the moves that reach it in the order of play, its promotions, how the chain proves the score, and what that rests on. Two programs that share no code check every line. Run these commands from the top folder of the repository:

Print the line of game 21
gzip -dc results/optimal.jsonl.gz | sed -n 21p
Build the frame solver
cd solver/frame && cargo build --release && cd ../..
Check every game with the frame solver’s verifier
solver/frame/target/release/taxman verify-results results/optimal.jsonl.gz
Check every game again, with a verifier in Python that shares no code with it
python3 solver/tools/check_results.py results/optimal.jsonl.gz

Both verifiers replay each game: every move legal, the largest prime first, no move left at the end, and the score as recorded. They check that each score is at most n more than the score of the game before it, and they work out again how the chain proves each score and what that rests on, so that an edit to the file cannot change either.

A replay shows that the moves are legal and score what the line says, but not that no other moves score more. That rests on how the chain proves the score, which each line names: a rule, such as the ceiling, or a search. The prover proves the scores of games 2 to 2,530 again, on the whole board, and its guide gives the commands.

The scores alone are also in results/b019312.txt, in the format of the OEIS.
