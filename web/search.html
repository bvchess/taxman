Chapter 5

Search

A search tries sets of promotions one candidate at a time, until it proves that none beats the best one found.

Once the board has split into frames, all that remains to choose is which candidates to promote. Before the frame solver searches, it asks whether an earlier game has posed this search problem already. When game n poses the search problem of one of the games just before it, game n is a repeat (chapter 2), and that game's promotions are the same as game n's. That's what happens in game 39. The new number (39) lands in a closed frame, where descending greedy keeps 39 and drops 22, and the frames with freedoms and their candidates stay as they were in game 38. Because of that, using the same promotions game 38 chose guarantees an optimal set of promotions in game 39.

Game 45 isn't so lucky. The maximal factors of 45 are 15, in frame 1, and 9, which with 27 made a closed frame of its own in game 44. 45 joins the two frames into one, so frame 1 changes, and game 45 poses a novel search problem. It has 8 candidates, so 256 sets of them. Game 5,060 has 1,380 candidates, and far too many sets to try one by one.

Branch and bound

The state lemmaLemma R1proved, proof on GitHub

What a node can still promote depends only on the frames its promotions leave.

P ∪ X is a promotion set exactly when each member of X is a factor of its home in state(P), and every frame of state(P) stays winnable when the player applies X.

A search tries the sets one candidate at a time. At each step it takes one candidate and splits the search tree in two. One branch promotes it, and the other goes on without it. Each point the search reaches is a node. All the while the search keeps the best game it has found, and each node has a bound, a limit on the sum of the promotions of any game in that branch, counting those already made. Every game in the search plays U*, so its promotions decide its score. A branch whose bound cannot beat the best game found is a dead end, so the search stops exploring that path. We call this way of searching branch and bound.

The figure's bound

The figure prunes with a simpler bound than the solver's, the sum of every candidate that the player could still add, one at a time, to the node's promotions. In its search, the player can promote candidates together exactly when U* with them is playable (Theorem X7).

The figure’s search of game 45 takes 13 nodes, and its bound drops 6 branches without looking inside them. When no branch remains, no set of promotions can beat the best one found.

The bound

The figure's bound adds up every candidate that the player could still add, one at a time, to the promotions the branch has already selected. Every set the player can promote passes this test, but so do many sets that cannot, so the bound is loose. At game 45's root the bound is 107, but eventually we learn the best set of promotions can only contribute 39.

The frame solver's bound is of the same kind. It is the heaviest set of candidates that passes a test, one that every set of legal promotions passes. Its test is far sharper, and chapter 6 explains it.

Learning from dead ends

Conflicts and nogoods

A conflict is a minimal part of the heaviest set that the player cannot promote, a median of two members in games 760 to 1,000 (conflicts). The solver keeps each as a nogood, a set the player cannot promote from the root (nogoods).

At each node, the solver checks whether the player can really promote the heaviest set that passes the bound's test. If it can, nothing in the branch does better, and the branch is done. If it cannot, the solver finds the few candidates in it that cause the trouble, often only one or two, which the player cannot promote all together. Any set the player can promote leaves at least one of them out, so the search splits on one of them. One branch promotes it, and the other goes on without it.

The solver remembers each dead end it finds. A set of candidates that the player cannot promote together at the root stays that way everywhere in the tree, so once the solver finds such a set, no other branch tries it again.

The prime-exchange theoremTheorem R2proved, proof on GitHub

Where two primes play the same part, the player can promote both a set of promotions and its mirror image, or neither, and we know the heavier in advance.

If exchanging the primes p < q maps the root onto itself, and no candidate is divisible by pq, p² or q², every heaviest promotion set has cp ≤ cq, where cr sums x/r over its multiples of r. At game 1,300, 41 and 43 are such a pair (prime exchanges).

Some pairs of primes play the same part in a game. In game 1,300, 41 and 43 are such a pair. Its candidates include 41 times 4, 6, 8, 9, 10, 12, 14 and 15, and 43 times the same eight numbers, and swapping 41 and 43 in every number leaves the frames, all together, as they were. So every set of promotions has a twin, made by the same swap, and the player can promote the twin exactly when the player can promote the set. A set that promotes 164 = 4 × 41, and no other of the sixteen, has a twin that promotes 172 = 4 × 43 in its place, and the twin weighs 8 more. Each swap trades a multiple of 41 for the same multiple of 43, or back, so it is easy to tell which twin is heavier, and the search tries only the heavier one.

A head start

The two starts of game 5,060

In sums of promotions, the part of the score a search chooses, the best is 570,330, and the search starts at 570,285 from game 5,059’s optimal set and at 569,735 on its own. The frame solver measured both, stopping each search after its first thousand nodes (the start of game 5,060). We measured what a start below the best costs a search at game 3,020 (a start below opt(n)).

A search does not start from nothing. The search of game n starts from the optimal set of game n − 1, which it carries over to game n (chapter 2), and that start is often optimal or close to it. Game 5,060’s search starts 45 points below the best score this way; from a start of its own, it would begin 595 below. The search drops a branch only when its bound cannot beat the best game found, so the nearer the search starts to the best, the more branches it can drop. A start far below the best can make a search many times longer.

The near-repeat lemmaLemma R7proved, proof on GitHub

A branch that poses part of an earlier game's problem adds no more than that game's best, so once the best game found reaches that much, the search may drop it.

Under three conditions against a game m, every completion of a node is a promotion set of m's root problem, worth at most a bound Z of its best.

Game n − 1 helps another way too. Where a branch of game n poses only part of the problem that game n − 1 posed, it can add no more than game n − 1's best, so once the search's best game reaches that, it drops the branch, by the near-repeat lemma. It is a repeat in part, since game n − 1’s search has already shown how much that part can add.

What proves a game

The dual-bound lemmaLemma R4proved, proof on GitHub

A search that drops only branches that cannot do better ends with the best set of promotions.

In an exact search, every promotion set heavier than the best found, and true to every mirror, lies in an open branch. So a search with no branch left proves P*, the heaviest promotion set's sum, equal to its best.

When the search has explored all branches, it has proved that no set of promotions beats its best one. It either tried each set or dropped it for a reason that shows it cannot do better: a bound, a dead end, or a heavier mirror image. So its best game is the best of the frame model, which is an optimal game when statement U holds. This is how the search proved the scores of 1,612 games of the chain.

A search can also stop early. No game of n scores more than the best score of game n − 1 plus n, the ceiling (chapter 2). A search whose best game reaches the ceiling has nothing left to find, so it can stop. That is how 494 searches of the chain ended, 490 of them at their start, before they explored a branch.

What it costs

The chart shows the number of nodes of every game of the chain whose search explored a node, 1,749 games in total. They climb from a single node in the small games to billions by the end, where game 5,060 took 1.2 billion.

How a subtree growsmeasured, evidence on GitHub

A subtree grows about 2.6 times for every 100 points of its gap.

In the profile of game 4,949, a subtree's steps rose 0.42 decades per 100 points of its gap, with a rank correlation of 0.88 to 0.96. Game 4,950's nodes sit 200 to 230 points higher, and its subtrees are 5 to 8 times larger (the hard games).

What decides the cost is the gap at each node, how far its bound is above the best game found. The search cannot drop a branch with a large gap, and the branch splits again and again before its bound comes down. In game 4,949, near the end of the chain, a subtree grew about 2.6 times for every 100 points of its gap.
