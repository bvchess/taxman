Chapter 1

A game is a set

Which numbers you take decides your score. The order follows from the set, and whether a set can be played at all is quick to check.

Your score is the sum of the numbers you take, so it does not depend on the order you take them in. The order matters only to keep every move legal: each number you take must still have a divisor in the pot.

Here are the nine moves of an optimal game in game 21. They can be played in several orders, and in every one of them each move takes the same tax. Step through them.

Sets, precisely

A set S ⊆ {2, …, n} is playable when some order of it is the moves of a legal game of n. Its weight is ΣS, the sum of its members. An optimal set, written S*(n), is the set of moves of an optimal game: a heaviest playable set. Some games can have more than one (game 425 is the first), so we say an optimal set (the theory's notation).

So the question for game n is not how to play but what to take. We call a set of numbers playable when some order of it is a legal game. An optimal set is a playable set with the largest sum, the set of moves of an optimal game.

Tax as payment

The lifting lemmaLemma P1proved, proof on GitHub

A number can be played if and only if one of its maximal factors is still in the pot.

Precisely.The maximal factors of x are x/p, for each prime p that divides x. At any point of a game, if a proper divisor d of x is in the pot, so is a maximal factor f of x with d | f.

A move is legal when one of its divisors is still in the pot, and only some divisors matter: a number's maximal factors, the number divided by one of its primes. 12 = 2 · 2 · 3 has the maximal factors 6 and 4, 9 has only 3, and a prime has only 1. If any divisor of a move is still in the pot, so is one of its maximal factors. So a move is legal exactly when a maximal factor of it is still in the pot.

Think of that factor as what pays for the move. Two moves cannot share a payment, because whichever is taken first sends the factor to the taxman. So a set can be played only if each of its numbers can be given a maximal factor of its own, from outside the set.

The graph, precisely

The maximal-factor graph of game n is a directed graph, with an edge from each number x to each of its maximal factors. Every edge leads to a smaller number, so the figures draw the edges as lines without arrowheads; in the board below, every edge runs one column to the right. The divisors of x are exactly the numbers that x reaches along its edges. The columns are the numbers' layers.

As the game is played, each number taken leaves the graph with its edges, so the board shows the graph of the numbers still in the pot. By the lifting lemma, x still reaches each of its divisors left in the pot through numbers left in the pot. So the tax of a move is everything it reaches on the board, and a move is legal exactly when it still has an outgoing edge.

The graph is the Hasse diagram of divisibility on {1, …, n}. The Hasse diagram of an order has an edge from each element to each element directly below it, and is drawn so that every edge points the same way, which is why it needs no arrowheads. A divisor d of x is directly below x when no third number is a multiple of d and a divisor of x, and that happens exactly when x/d is prime.

Draw every number joined to its maximal factors, and the game becomes much easier to play. The board below is that maximal-factor graph. Its columns count prime factors: the primes stand in the column at the right, 1 beyond them, and each number sits one column to the left of its maximal factors, so every line runs to the right. Taking a number sends the taxman everything it reaches by following its lines to the right, and every number taken leaves the graph with its lines. A number stands up while it still has a line to its right.

You can see what each move will cost before you make it, and what it will leave for the moves after it. That makes the game far easier than on the plain board of the introduction.

The playability theoremTheorem P2proved, proof on GitHub

A set can be played exactly when each member can be paid for by a maximal factor of its own, from outside the set, with no circle in what must come first.

Precisely.S ⊆ {2, …, n} is playable iff it has a payment scheme, a one-to-one choice of a maximal factor outside S for each member, whose precedence is acyclic. Then every topological order of the precedence is a legal game.

Franklín and Moniot

Their Theorem 1 says the same in the language of matchings: a set is playable iff it is the set of upper ends of a matching of the maximal-factor graph with no flat alternating cycle (the paper; how the theory relates to it).

A payment for each number is not quite enough, because the order can still tie itself in a knot. A move takes all of its divisors in the pot, not only the one that pays for it, so it can take a factor that another move was counting on. In game 21, 9 is paid for by 3, and 15 would take 3 as tax, so 9 must come before 15. And 9 divides 18, so 9 must come before 18 as well, or 18 would take it.

Rules like these say which moves must come before which. A set can be played exactly when its numbers can be paid for in a way whose rules never run in a circle, each move before the next and the last before the first. Then any order that keeps the rules is a legal game.

Peel

Trying every way to pay would be slow. A quicker test never has to guess. It pairs numbers with their payments one at a time, using only two kinds of safe step:

  • A number with only one maximal factor left to pay with takes it.
  • A factor that only one number can still use goes to that number.

Each step takes its pair out, and the next step looks at what is left. If every number gets paired, the set is playable. If the steps run out with numbers left over, it is not. It never matters which safe step was taken first. We call this test peel.

The peel theoremTheorem P4proved, proof on GitHub

Peel decides whether a set can be played, whichever safe steps it takes in whichever order.

Precisely.A front move pairs a member that lists one live factor with it; a back move pairs a live factor that one member alone lists with that member. Each keeps an instance playable, and keeps it unplayable. An instance is playable iff a run of peel pairs every member, and such a run yields an acyclic payment scheme.

Peel in the code

The frame solver decides playability by peel in solver/frame/src/playable.rs.

In game 21, peel pairs 19 with 1, the only factor it has, and 9 with 3 for the same reason. Once 3 is gone, 15 has only 5 left and 21 only 7, and the rest follow. The pairs it finds are the payments of the game itself.

A run of peel that pairs every number also gives a legal order: play each number before any move that would take it, or its payment, as tax. So a playable set comes with a game, quickly.

The loop

When peel gets stuck on numbers with two maximal factors, a loop is to blame. Take the numbers 10, 14, 15 and 21, with only the primes 2, 3, 5 and 7 left to pay with. Each of the four is the product of two primes, which are its maximal factors, so in the maximal-factor graph it has a line to each of two primes. Unfold the graph, putting each number between its two primes, and the loop appears: the four make a square, 10 = 2 · 5, 15 = 5 · 3, 21 = 3 · 7 and 14 = 7 · 2. Every number has two ways to pay, and every prime can pay for two numbers, so peel has no safe step. Try to play all four.

The loop ruleProposition P11proved, proof on GitHub

Numbers that each have at most two maximal factors can all be played exactly when their edges form no loop.

Precisely.An instance whose members each list at most two factors is playable iff its lists are linearly independent over GF(2), iff its graph is a forest. The graph's vertices are the factors and one more, the ground, and each member is an edge, between the two factors it lists or from the one it lists to the ground.

Whatever order you choose, the first number takes both of its primes as tax. That leaves two primes for the other three numbers, and one of them is always stuck.

The same holds for any numbers that each have at most two maximal factors. Draw each one as an edge between its two maximal factors, or, if it has only one, as an edge from that factor to the ground, one more point that all such numbers share. They can all be played exactly when their edges contain no loop. The ground matters: 4 can pay only with 2, 9 only with 3, and 6 needs one of the two, so one of the three is always stuck. Their edges make the loop ground – 2 – 3 – ground.

Three maximal factors are too many for the rule. With 4, 6, 10 and 15 left to pay with, the lines of 12, 20 and 30 close a loop, 30 – 6 – 12 – 4 – 20 – 10 – 30, yet all three can be played: 20, then 12, then 30. A number with three maximal factors is not an edge, and for it the question goes back to peel.

So the rule covers only part of the game, but an important part. Every number with two prime factors, such as 95 = 5 · 19 or 49 = 7 · 7, has at most two maximal factors, all of them primes. These numbers make up layer 2 of the graph, and chapter 3 uses the rule to find exactly which of them above n/2 every optimal game plays.

Three factors, precisely

The length propositionProposition Q4proved by computation, proof on GitHub

In game 833 every optimal game has 362 moves, and the longest games have 363.

Precisely.In game 833 = 7² · 17 a heaviest game of 363 moves scores 218,197, which is 29 less than opt(833) = 218,226. The prover and a maximum matching compute it.

Along the way: game 833 OpenClose

Taking more numbers does not always score more. In game 833, every optimal game makes 362 moves, yet some games make one more. The longest of those still scores less: they play five smaller numbers where the optimal game plays four larger ones.

The trade happens below n/2. Each of the nine numbers is a maximal factor of a number the optimal game plays, and a number taken as a move cannot also pay for another. The optimal game takes the four large ones and pays for those numbers some other way. The longest game leaves the four to pay, and takes five smaller ones instead.
